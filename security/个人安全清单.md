# 个人电脑安全清单（VAL 反用版）

> 把"判级三问"反过来用于个人防护：
> **收到任何"声称"，先问——验证条件谁声明的？保证什么？有没有独立于声称者的锚？**
> 无锚 = L0 = 不信任；有独立锚（哈希/签名/官方渠道）= 验过才行动。

---

## 一、判级三问（个人安全版）

1. **谁声明的？** 这条消息/文件/链接的"可信来源"是自证的，还是有独立方背书？
2. **保证什么？** 它声称"安全/官方/正常"——保证到哪一层？（没验过的"安全"=无保证）
3. **锚在哪？** 我能主动验证它的独立锚吗？（官方 sha256、数字签名、官方域名——注意：必须是**我主动发起**的验证，不是对方给我的链接）

## 二、场景对照表

| 场景 | 声称 | 应做的验证（独立锚） | 判定 |
|---|---|---|---|
| 钓鱼邮件"账户异常/中奖" | 我是银行/官方 | 悬停看发件域名 → **自己打开官网**（不是点邮件里的链接） | 无独立锚 → L0，删除 |
| 下载软件 | 官网安装包 | 官网公布的 **sha256** + 数字签名（`verify_checksum.py`） | 匹配=L2 通过才装 |
| 陌生脚本/程序 | 运行安全 | **沙箱/虚拟机**里跑（限制执行域） | L0 代码 → 只在 ODD 内执行 |
| AI 助手"这代码没问题" | LLM 自证 | 自己读代码/跑测试 | L0 → 当它没验过 |
| 客服来电要验证码 | 官方客服 | **挂断，主动**打官网电话回拨 | 无独立锚 → L0 |
| 陌生 U 盘/二维码 | 内容安全 | 只读挂载/不扫 | 未知来源 → 不碰 |
| "朋友"发来链接 | 朋友转发 | 域名/短链接展开后核对 | 转发≠背书，仍要查锚 |

## 三、具体命令（Windows）

```powershell
# 1. 校验下载文件（sha256 与官网比对）
python verify_checksum.py <文件> <官网公布的sha256>

# 2. 生成某文件哈希（备用）
python verify_checksum.py --gen <文件>

# 3. 查文件签名（数字签名 = L3 级锚）
Get-AuthenticodeSignature <文件路径> | Select Status, StatusMessage, SignerCertificate

# 4. 陌生脚本进沙箱（PowerShell 限制执行域）
#    先看内容再决定；永远别对不可信脚本直接运行
Get-Content <脚本.ps1> -Head 50   # 先读前 50 行

# 5. 防火墙/端口自检（锚 = 本机事实）
Get-NetTCPConnection -State Listen | Select LocalPort, OwningProcess
```

## 四、密码与 2FA（多锚思维）

- 纯密码 = 单锚（你记得的东西）；
- **2FA = 第二独立锚**（你有的设备）——两条独立链，一条被断还有另一条；
- 密码管理器 = 让每个网站用独立密码（每站一个锚，不共享）；
- 重要账户单独强密码，**从不复用**（复用 = 一个锚被破全部失守）。

## 五、底线（工具会说的"不"）

- **没有独立锚的"官方"一律按 L0 处理**——哪怕它说得再像真的；
- **验证必须是"我主动发起的"**：主动开官网、主动查哈希、主动回拨电话——被动给的验证链接本身就是可疑信号；
- **未知代码的执行域要受限**：沙箱/虚拟机就是给它一个 ODD，越界即止；
- 2FA 是第二锚，不是万能——验证码也请只给"我主动发起的"服务。

> 这套清单是 VAL 框架的反用：它不能让你 100% 安全（没人能），
> 但它让"声称"和"保证"之间的差距在你眼前可见——这正是它该做的。
