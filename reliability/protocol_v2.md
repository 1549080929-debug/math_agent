> 禁止参考任何已含判级结果的文档（docs/06 §7、docs/07、verifier.py ANCHOR_LEVELS、val_standard.py CASES）。
> 版本：v2.0（2026-08-20 首轮）→ v2.1（第一轮分歧修订）→ v2.2（第二轮缺口修订）→ **v2.3（第四轮修订）**。

## 0. 判级对象

对"验证方案/裁判"判级。**判"当前实现的运行时判定机制"，不判"锚的潜力"、不判"基准质量"。**

## 1. 判级三问（Q1→Q2→Q3，顺序回答）

### Q1 规格来源：验证条件由谁声明/最终判定由谁做出？

| 选项 | 判定辅助问题 |
|---|---|
| **LLM 声明** (llm) | 验证条件（"什么算对"）或最终判定，由 LLM（含被验证的模型本身、另一个 LLM、GPT-4 标注方案）写出/做出？ |
| **确定性规则** (rule) | 验证条件从题面/代码/文本机械派生（正则、解析器、schema、阈值规则）？ |
| **客观真值** (truth) | 验证条件锚定在独立于声明者的客观真值（题面给定的数学条件/方程、外部文档、人工金标、实测值、权威源）？ |
| **可判定系统** (decidable) | 验证条件编码进可判定的形式系统（符号求解器、类型系统、证明内核）？ |

**Q1 边界规则（全部适用时先看规则再回答）：**

- **R1 判运行时，不判基准**：评测基准里的金标 ≠ 运行时判定的锚。若最终判定由 LLM 做出，即使配套基准有金标，判定机制按 LLM 声明处理；基准金标只标注为"基准锚"，不计入运行时等级。**纯评测基准/测试集（不输出运行时判定）→ N/A（非运行时验证器）**，除非其内部嵌有运行时判定机制（则按机制判）。
- **R2 混合系统按组件拆分**：一个系统若有多个判定组件，逐个组件判，输出格式 "Lx（组件名） + Ly（组件名）"。**报告等级 = 判定路径上最弱锚的那个组件**。
- **R3 证据锚 ≠ 判定锚**：检索/工具提供外部证据（证据组件可达 L2/L3），但"声明 vs 证据"的对齐判定若由 LLM 做出，判定组件按 LLM 声明处理。
- **R4 silver anchor**：确定性重计算（如让工具先算再比对）若只验证"计算过程"而无独立金标验证"答案本身"，按确定性规则（L1）处理，不算客观真值（L2）。
- **R5 统计训练分类器**：训练出的统计验证器——训练标签若为人工/客观金标 → 客观真值（L2）；训练标签若为 LLM 生成 → 按 LLM 声明（L0）。
- **R6 形式内核**：证明内核（Lean/Coq/类型检查器）判定证明 → 可判定系统；但**定理陈述/分情况覆盖若由 LLM 生成，陈述层单独标注 L0**，报告 "L4 内核 + L0 陈述层"。
- **R9 题面真值 vs LLM 派生规则（第一轮新增，v2.3 补充采样澄清）**：**题面给定的数学条件/方程/已知事实 = 客观真值（L2）**——它独立于 LLM 的声明，是问题本身的真值；**从 LLM 自身输出（解题文本、自述 final_check）机械派生的规则 = L1**（信任递归，规格来自被验证者自己）。判断标准：验证条件在 LLM 答题**之前**就已存在 → truth；从 LLM 答题**之后**的文本/声明中提取 → rule。**采样验证澄清**：采样对照题面条件/客观真值（逐点代入题面验证）→ truth（L2）；纯统计自评（无外部真值对照，如自一致性投票）→ 按 LLM 声明（L0）。
- **R10 设计者自造规则（第一轮新增）**：设计者/作者自造、未经外部验证的确定性规则 = **L1**（即使其输入是客观数据）——规则本身的规格由设计者声明，无独立背书。只有锚定在客观真值（L2）或**已验证的外部决策规则**（L3，如 Alvarado/PERC）才算升层。对比：R9 的题面真值在答题前已存在；R10 的自造规则在设计时由人声明，两者都不是 LLM 声明，但也都不构成独立外部背书，判 L1。
- **R11 判定路径（第一轮新增）**："判定路径" = 从证据到**最终判定**所经过的组件链。只提供证据、不参与最终判定的组件不进路径，仅作标注。报告等级 = 路径上最弱锚组件。
- **R12 符号工具锚（第二轮新增）**：符号计算引擎（SymPy solveset/simplify、SMT 求解器、类型检查器、执行内核/解释器）是**可判定系统**（Q1=decidable）——它们对形式对象执行机械、确定性的算法，不是"手写规则"。判定测试：**产生判定的是现成形式引擎（引擎说）还是人写的决策程序（人规定）？** 形式引擎 → decidable（正确性用法=L2 用法降级，完备性用法=L3）；人写决策程序（阈值、正则、清单）→ rule（L1，见 R10）。
- **R12b 定理支撑的穷举（第四轮修订）**：R12 的判定测试补充——**有定理/证明背书的穷举过程**（如闭区间极值定理保证"端点+驻点"是极值候选的完备集；类型系统的域穷举）属于可判定系统（Q1=decidable，完备性用法→L3）；**无完备性背书的启发式枚举**（任意采样点集合、经验列表）才是规则（L1）。判据：穷举的完备性是否可由已知数学定理/形式论证保证——能保证 → decidable；不能 → rule。
- **R13 判定路径归属（第二轮新增）**：先确定**哪个组件产出最终判定**（被消费为该系统的"判定"的那个输出）；只提供证据/特征/解释的组件不在路径上（作为标注报告）。报告等级 = 判定产出组件的等级（沿路径最弱锚）。例：诊断系统最终给出诊断的组件 = 判定产出者；提供金标 grounding 的感知层、事后解释层都只是标注。若判定产出者本身是统计分类器 → 按 R5（训练标签锚定）。
- **R14 hedge 承诺约定（第二轮新增）**：证据不足（CONF=low/medium）时，**仍必须输出单一承诺等级**（取与现有证据一致的最弱锚），备选解释写在 JUST 里。"Lx+Ly" 多标签**仅限**已确证的混合判定路径（各组件等级均有证据），不作为 hedge 用。等级比较以单一承诺值为准（最弱锚）。
- **R15 LLM 生成的验证期望（第四轮修订）**：若验证期望（测试断言、比对规格、判定标准）由 LLM 生成、再被确定性执行——判定路径含 L0 组件（期望来自被验证者的同源生成器，信任递归），报告最弱锚 **L0**；确定性执行只作证据标注。对比：期望由人工/题面/平台给定 → 按 R9/R10 正常判（题面真值→L2、自造规则→L1）。
- **锚语义正交声明（v2.3）**：锚语义类型（intent/truth/effect，docs/13）是**正交标注**，不影响等级判据——同等级可承载不同语义，语义决定判定含义而非等级。

### Q2 保证类型：判定保证到什么程度？

| 选项 | 含义 |
|---|---|
| **无** (none) | 没有任何确定性保证（纯自证/置信声明） |
| **正确性** (correctness) | "提出的候选都成立"——代回、抽样、单点满足、统计阈值 |
| **完备性** (completeness) | "没有候选被遗漏"——要求性质被编码进可判定系统 |

**Q2 边界规则：**

- **R7 混合保证取弱档**：若实现 = simplify + 抽样兜底，取"正确性"（较弱档），不算完备。
- **R8 经验数字 ≠ 完备**：召回率 99.3%、AUC 0.98 等经验指标是正确性层证据，不构成完备性声称。

### Q3 覆盖范围（仅 Q2=完备性 时回答）

| 选项 | 含义 |
|---|---|
| **单性质** (single) | 对单一可判定性质完备（解集等价、类型符合、单条决策规则） |
| **领域** (domain) | 对整个领域性质完备（类型系统全域、证明内核） |
| **声称任意** (universal) | 声称对任意性质完备 → **L5 否决**（Rice 定理，不可判定） |

## 2. 判级程序（顺序判断，先中先得）

```
1. Q2=完备性 且 Q3=声称任意        → L5（否决：原则上不存在）
2. Q2=完备性 且 Q3=领域            → L4
3. Q2=完备性 且 Q3=单性质          → L3
4. Q2=正确性 且 Q1=可判定系统      → L2（标注"用法降级，可抬级"）
5. Q2=正确性 且 Q1=客观真值        → L2
6. Q2=正确性 且 Q1=确定性规则      → L1
7. 其余（Q1=LLM 声明 / Q2=无）     → L0
```

## 3. 判定矩阵（速查）

| 保证＼规格 | LLM 声明 | 确定性规则 | 客观真值 | 可判定系统 |
|---|---|---|---|---|
| 无 | L0 | L0/L1 | L0/L1 | L1 |
| 正确性 | L0 | L1 | L2 | L2（可抬级） |
| 完备性(单性质) | — | — | — | L3 |
| 完备性(领域) | — | — | — | L4 |
| 声称任意 | — | — | — | L5 否决 |

## 4. 特殊标签

- **非验证**（non-verification）：分类学/综述/理论框架——不判定对错，只分类维度。输出 "N/A"。
- **理论形式化**：形式上是 L3/L4 风格但对象是 L0 现象（如把"自验证"形式化）——如实描述，标注"理论"。

## 5. 评分输出格式

每个语料条目输出：

```
Q1: <llm|rule|truth|decidable|n/a>
Q2: <none|correctness|completeness|n/a>
Q3: <single|domain|universal|n/a>          # Q2≠completeness 或非验证时为 n/a
LEVEL: <L0|L1|L2|L3|L4|L5|N/A>             # 混合系统可输出 "Lx+Ly"
CONF: <high|medium|low>                    # 证据充分性自评
JUST: <一句话依据，引用机制事实，不引用任何判级结果>
```

## 6. 评分纪律

1. **只依据语料证据包里的机制描述**；证据不足 → 标 CONF=low，按现有证据判，不脑补；
2. **不看任何已有判级**（docs/06 §7、docs/07、verifier.py、val_standard.py）；
3. 混合系统**必须拆分组件**再判；
4. 拿不准边界时，按"最弱锚"原则取低不取高（宁可 L0/L1 不可虚高）。
