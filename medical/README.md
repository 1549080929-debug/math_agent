# 第三章 · 医疗诊断：LLM 诊断推理的失败模式与验证框架

> 方法论第三验证场。定位：**研究**，不是诊断工具。
> 延续一条脉络：每一层都必须挂接可验证的裁判，而裁判必须理解"完备性"而不只是"正确性"。

---

## 一、定位与伦理边界（先立规矩）

1. **研究定位**：本项目研究 LLM 诊断推理的失败模式与验证框架，
   **不构成医疗建议，不用于真实患者，不宣称诊断能力**；
2. **数据**：全部为**合成虚构病例**（教科书式病例改写），无任何真实患者数据；
3. **输出纪律**：任何"诊断"结论必须附不确定性声明与建议转诊/检查的诚实失败出口；
4. **价值主张**：不是"提高诊断准确率"，而是**降低"自信地错"的风险**——
   让系统知道自己不知道（UNSURE → 建议进一步检查），这是医疗最缺的能力。

## 二、方法论映射

| 方法论（第一/二章） | 医疗诊断的对应 |
|---|---|
| 三态裁判 PASS/FAIL/UNSURE | 诊断确定 / 诊断错误 / **信息不足→建议检查**（UNSURE 是医疗里最珍贵的状态） |
| 失败模式分类学 | 诊断失败模式：漏鉴别诊断、忽略红旗征、自信错诊、锚定效应、信息不足仍下结论… |
| 信任分层（LLM声明→代码执行） | LLM 提鉴别诊断 → 规则/知识库检查症状覆盖与指南一致性 |
| 审计先行 | 合成病例测试床（确诊标签）→ 基线测量 → 失败模式分类 |
| 诚实失败出口 | "无法确定，建议进一步检查/转诊"（而不是自信地给错诊断） |

## 三、价值窗口假设（待实测）

```
医疗诊断的价值窗口 = {LLM 会自信地错（高影响）}
                    ∩ {标准答案存在（确诊标签）}
                    ∩ {结构可验证（症状覆盖/鉴别诊断完整性/红旗征检测）}
```

与数学的区别：标准答案存在（确诊），但价值不在准确率，在**诊断推理的完整性验证**
（有没有漏掉致命鉴别诊断、有没有忽略红旗征）。数学验证的是"答案对不对"，
医疗要验证的是"推理过程有没有盲区"——更接近完备性而非正确性。

## 四、第一步（审计先行）

1. **合成病例测试床**：10+ 例教科书式病例，覆盖常见病/鉴别陷阱/红旗征/罕见病，
   每例带确诊标签 + 设计意图（预期失败模式）——`cases.json`；
2. **基线测量**：直接让 LLM 诊断（鉴别诊断列表 + 最可能诊断 + 置信度 + 红旗征判断），
   统计：准确率、置信度校准、鉴别诊断完整性、红旗征识别率；
3. **失败模式分类**：把基线错误按第二章的分类学归类（自信错诊/漏鉴别/忽略红旗…）；
4. **验证器可行性**：结构性检查（症状-诊断覆盖矩阵、红旗征清单、鉴别完整性）能否
   抓住基线错误——测"裁判"本身可不可用，再决定建不建架构。
