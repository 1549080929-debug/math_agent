**一、我对贵团队工作的理解**

贵团队发布的 JADE 7.0 是智能体安全领域的重要工作：JADE-MCP-CLS 分类（首个针对恶意 MCP Server 的系统性风险分类，6 大类 33 小类）和配套的近百个恶意 Server 实例集合，系统性地覆盖了直接投毒（工具描述注入）与间接投毒（外部资源污染）两种攻击。贵团队基于 Cursor 环境对 8 款主流模型的评测（直接投毒平均 ASR 83.0%、间接投毒 80.3%）清楚地表明：当前 LLM 内生防御手段对 MCP 生态投毒攻击普遍失效。这一结论与我在自研测试床和 AgentDojo 官方基准上的观察高度一致。

**二、我的工作：一个解释 "为什么" 的框架**

我提出了 VAL（Verification Autonomy Levels，验证自主等级 L0–L5）框架（arXiv:2608.19009），按 "验证 / 防御规格的来源" 给防御方案分级：L0 模型自述（"运气" 防御，换攻击 / 模型 / 基准零会移动）、L1 确定性规则（可被改写绕过）、L2 客观真值（分布内有效）、L3/L4 可判定系统（结构保证，与模型行为无关）。核心论点是：防御失败的方式 = 其锚失效的方式。我在自研测试床（~5400 次调用）和 AgentDojo 官方基准上验证了这一点：一个 "确认门 + 参数沙箱" 的 VAL 选型栈在 AgentDojo 上 0% ASR 且零 utility 损失，而 "提示加固 + 关键词过滤" 的直觉栈同为零但机制上是模型运气。第二篇论文《The Anchor Decides》为 working paper，完整文本与代码见 GitHub。

**三、用贵团队公开实例做的验证（真实 MCP 协议）**

我直接运行了贵团队发布的 set_alarm_clock.py（FastMCP server，stdio transport），通过真实 MCP 协议验证了三种配置，投毒描述与返回全部由贵团队代码生成，原文件仅做了参数化适配。

| 配置 | ASR | 关键发现 |
| --- | --- | --- |
| 无防御（ND） | 87.5% (14/16) | 模型被投毒驱动真实执行发邮件 / 发推 —— 复现贵团队 83% 的评测结论 |
| 提示加固 + 关键词过滤（N） | 6.2% (1/16) | M6（post_tweet 变体）真实漏过 —— 关键词表没有 "post"/"tweet" |
| 确认门 + 参数沙箱（V） | 0.0% (0/16) | 模型被驱动 93.8% 仍全拦 —— 白名单枚举，与模型行为无关 |

分项看，直接投毒 7/8、间接投毒 7/8 均被驱动执行——两种投毒路径都复现了贵团队的结论（官方 83.0% / 80.3%）。

我特别重视结果的可追溯性与公平性：51 个用例的完整 trace 全部存档，任何数字均可回溯核对；并附了 8 项公平性审计清单（三配置使用完全相同的 MCP server、投毒内容、LLM 参数与判定标准）。实验过程中发现并修复了 4 个 harness bug（工具集不完整、prompt 缺工具名导致间接投毒链未真正发生、set_alarm_clock 未入 D4 schema 导致误拦良性操作），修复后模型被驱动程度从 18.8% 升到 93.8%（更接近真实攻击强度），V 栈依然全拦——结果在更严苛条件下依然成立。详细报告、代码与 trace 见：[https://github.com/1549080929-debug/math_agent/tree/main/agentsec/jade](https://github.com/1549080929-debug/math_agent/tree/main/agentsec/jade)
