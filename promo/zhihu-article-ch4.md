# 我把框架的预测先写死，然后拿外部证据去撞：4/5 命中

> 副标题：一个"反向验证"实验——LLM 验证框架 VAL 的第四章
>
> 论文：Grading the Graders: Verification Autonomy Levels (L0–L5) for LLM Reasoning
> arXiv:2608.19009 — https://arxiv.org/abs/2608.19009
> 代码与数据：https://github.com/1549080929-debug/math_agent

---

## 开场：预测力，是"分类学"和"理论"的分界线

一个框架，如果只能解释它自己的训练数据，那它只是总结；如果它能对没见过的领域做出**事前预测**，并且预测被证据接住，它才配叫理论。

前三章，我是从数据里归纳出框架的（自下而上）。第四章，我要反着来一次：**把框架的预测先写死、签上日期，然后拿外部证据去撞**（自上而下）。如果预测全中，框架获得外部验证；如果半数不中，框架需要修订——**两种结果都是产出**，尤其后者，它暴露框架的边界。

结果：**4/5 命中，第 5 条不可测而非被反驳。**

## 一、背景：三章归纳出的 VAL 框架

之前三章实验（数学验证 / 行为观测 / 医疗诊断）让我归纳出一个框架——**VAL（验证自主等级）**：

| 等级 | 判定依据 | 保证 |
|---|---|---|
| L0 | LLM 自证（"我检查过了"） | 无 |
| L1 | 题面/代码确定性规则 | 确定性匹配 |
| L2 | 客观真值 / 金标 | 正确性 |
| L3 | 可判定系统（解集等价/类型检查/决策规则） | 单性质完备 |
| L4 | 领域级证明系统 | 领域完备 |
| L5 | 通用完备验证 | 不可判定（Rice 定理） |

核心理念：**层级由"锚"决定，不由"裁判"决定**——代回验证永远发现不了"没被提出的候选"（完备性盲区），采样加密一万倍也跨不进 L3。

三章的实证模式出奇一致：**LLM 太强 → 准确率窗口为空**（数学 16/15/13 vs baseline 20/20、医疗教科书 10/10、行为检测 FPR 从 92% 压到 30% 但存在结构性天花板）。

## 二、第四章：预测先写死

第四章选**代码生成**——它有最密的 L3 锚生态（编译器、类型检查器现成）。动手前，我先把 5 条预测写进文档、签上日期，每条附**可证伪判据**：

| # | 预测 | 可证伪判据 |
|---|---|---|
| P1 | 测试选择有"测试预言机"上限 | 若 test-based 选择无天花板提升准确率 |
| P2 | LLM 自评有效用但无保证 | 若自评稳定可靠 |
| P3 | 类型检查是性价比最高的 L3 锚 | 若类型信息对正确性无增益 |
| P4 | LLM 写的测试本身可疑（信任递归） | 若 LLM 测试无错误无遗漏 |
| P5 | 执行反馈 >> 自评 | 若自评不弱于执行反馈 |

纪律：**预测先于证据，事后不得改动**——否则就是挑证据（cherry-picking）。

## 三、文献撞墙：4/5 命中

- **P1 ✅**：AlphaCode 大规模测试过滤、CodeT 生成测试+执行选择、LEVER 执行重排——而 LEVER 作者自己写："获取测试用例本身就是挑战"。测试预言机上限，文献确认。
- **P2 ✅**：Olausson 等人《Is Self-Repair a Silver Bullet?》——不是银弹；Huang 等人《大模型尚不能自我纠错》——无外部反馈时自纠错常失败。
- **P4 ✅**：最干净的工业实证——**Meta 的生产工具 TestGen-LLM 对 LLM 生成的测试必须再过验证过滤器**。连 Meta 都知道模型写的测试不能直接用：这就是信任递归在规格层的现身。
- **P5 ✅**：Reflexion / CodeAct / 自我调试，全部以执行反馈为核心，全面碾压无反馈——L2/L3 锚 > L0 自评。

## 四、P3 实验：164/164，窗口空

P3（类型信息提升正确性）没有直接文献，我跑了实验：

1. HumanEval 164 题，把题面的类型标注**全部剥掉**，裸生成 → **164/164 全对**；
2. 手写 6 道**带陷阱的非经典难题**（自定义数字序列、转义解压、会议排期、位操作、奇偶配对、混合展平）——裸生成 → **6/6 全对**。

准确率窗口两次为空。deepseek-chat 对代码生成太强，**没给"类型信息"留任何可提升的空间**。P3 的准确率推论在此模型上不可测——这不是主张错了，是此模型无窗口。

## 五、唯一的亮点：mypy 抓到了测试的盲区

带类型条件下，6 道难题里有 1 道失败（转义解压，最容易踩的坑）。**mypy 报了 1 个测试发现不了的类型错误**，反馈一轮，修复，PASS。

这一个样本是定性的，但方向明确：**L3 锚（类型检查器）入环，确实抓到了 L2 测试的盲区**——这正是框架说"完备性只能由可判定系统给"的现场演示。

## 六、框架第 4 次命中"LLM 太强"

"LLM 太强 → 准确率窗口空"这个泛化，现在被四个领域确认：

```
数学（baseline 20/20）→ 医疗（教科书 10/10）
→ 代码训练集内（HumanEval 164/164）→ 代码手写难题（6/6）
```

包括我**特意设计来打败它的题目**。这不是巧合了，是规律。

## 七、方法论彩蛋：审计抓出我自己的测试错误

跑实验前，按项目纪律先"审计测试"——用手写 canonical 解法自验。**抓出 3 个我拍脑袋写错的期望值**（比如把 `kth_custom_number(1)` 写成 27，真值是 57）。

"裁判的裁判也需要裁判"——连实验设计本身都逃不掉。没有这一步，我会拿错误的金标准跑出假结果。

## 八、意义与边界

**意义**：框架通过了反向测试——**事前预测 4/5 被独立证据支持，第 5 条不可测而非被反驳**。预测力，是分类学和理论的分界线。

**边界（诚实版）**：
- 单模型（deepseek-chat），且该模型对代码生成异常强；
- P3 的准确率推论要闭合，需要更弱的模型或训练集外的题目；
- 文献证据为摘要级核实（arXiv ID 逐条验证过标题/作者）；
- 全部数据、代码、预测文档开源可复现。

## 结尾

我给验证器分级，不是想分个高低贵贱——是想让"verified"这个词恢复它本来的分量。

而第四章教会我的事是：**框架的真正价值，不在它解释了什么，在它敢预测什么。**
