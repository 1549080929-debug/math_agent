**1.**
我们做了一次"反向验证"：把框架的预测先写死、签上日期，然后拿外部证据去撞。
结果：4/5 命中，第 5 条不可测。
框架第一次被"事前预测"检验，而不是"事后解释"。

**2.**
背景：前三章（数学 / 行为观测 / 医疗诊断）从失败里归纳出一个框架——VAL：
LLM 验证的 L0–L5 自主等级（L0=LLM 自证"我检查过了"，L3=可判定系统完备，
L5=不可判定，Rice 定理）。

**3.**
第四章选代码生成。动手前先写死 5 条预测，每条附可证伪判据：
P1 测试选择有"测试预言机"上限
P2 LLM 自评有效用但无保证
P3 类型检查是代码域性价比最高的 L3 锚
P4 LLM 写的测试本身可疑（信任递归）
P5 执行反馈 >> 自评

**4.**
文献证据：4/5 命中。
P1 ✅ AlphaCode/CodeT/LEVER——LEVER 作者自述"获取测试用例本身就是难题"
P2 ✅ "Self-Repair 不是银弹"(Olausson)、Huang "大模型尚不能自我纠错"
P4 ✅ Meta 生产工具 TestGen-LLM：LLM 生成的测试必须再过验证过滤器——工业界实锤信任递归
P5 ✅ Reflexion / CodeAct / 自我调试——执行反馈全面碾压无反馈

**5.**
P3 没有直接文献，我们自己跑实验：
HumanEval 164 题全部剥掉类型标注，裸生成 → 164/164 全对。
准确率窗口空——模型没给"类型信息提升正确性"留任何空间。

**6.**
不服，手写了 6 道带陷阱的非经典难题：
自定义数字序列、转义解压、会议排期、位操作、奇偶配对、混合展平。
裸生成 → 6/6 全对。LLM 太强，验证器无从下手。

**7.**
唯一亮点：带类型条件下 1 道题失败（转义陷阱），
mypy 抓到测试发现不了的类型错误，反馈一轮就修复 → PASS。
L3 锚（类型检查器）入环，确实抓到了 L2 测试的盲区。

**8.**
意义 1："LLM 太强 → 准确率窗口空"在四个领域被确认：
数学 / 医疗 / 代码训练集内 / 代码手写难题。
这不是巧合了，是规律。

**9.**
意义 2：框架通过了反向测试——事前预测 4/5 被独立证据支持，
第 5 条不可测而非被反驳。
预测力，是"分类学"和"理论"的分界线。
