# 对抗性预测实验：完整报告（含审计更正）

> 流程：生成预测表 → 实跑 baseline vs 系统 → LLM 复盘 → **人类 + SymPy 审计更正**（本报告的重点）
> 日期：2026-08-18　模型：deepseek-chat

---

## 一、实验设计

让 LLM 生成 5 道"它预测 baseline（直接单次求解）会翻车"的题，每题写明：
预测失败模式（具体到哪一步）、翻车根因、系统凭什么能对。
然后实跑两个对照组，最后让 LLM 对照预测表复盘。

---

## 二、预测表（阶段1，原样）

| 题 | 题目 | 预测的失败模式 |
|---|---|---|
| 1 | f(x)=x²-2ax+a²-1 在[0,2]上最大值为3，求 a | 只考虑对称轴在区间内，漏端点取最大值的情况 |
| 2 | 解 x²-2√5x+2=0 并化简根式 | 化简 √(20-8) 时忘除以2，写成 √5±2√3 |
| 3 | f(x)=x²-2mx+m²-1 与 y=2x-3 两交点，求 m | 判别式符号错误（大于写成小于） |
| 4 | 解 x²-3x+1=0 并化简根式 | 求根公式漏分母，写成 3±√5 |
| 5 | f(x)=x²-2ax+a²-1 在[0,2]上最小值为-1，求 a | 只考虑对称轴在区间内，漏端点取最小值的情况 |

## 三、实跑结果（阶段2，摘要）

| 题 | baseline 实际 | 系统实际 | 系统验证状态 |
|---|---|---|---|
| 1 | 推理正确方向（a=2成立、a=-2不成立）* | 分类讨论，但最终只得出 a=2 | PASS,UNSURE,UNSURE,UNSURE,PASS |
| 2 | ✅ 正确 √5±√3 | ✅ 正确 √5±√3 | PASS,UNSURE |
| 3 | ✅ 正确 m>1/2 | ✅ 正确 m>1/2 | UNSURE,PASS,UNSURE |
| 4 | ✅ 正确 (3±√5)/2 | ✅ 正确 (3±√5)/2 | 全 UNSURE |
| 5 | 推理正确（a∈[0,2] 都符合）* | 推理正确，但**最终答案自相矛盾**：boxed "0 或 2" | PASS,UNSURE,UNSURE,UNSURE |

*标注：baseline 输出被实验脚本截断（800字符），仅能确认其可见推理过程。

## 四、LLM 复盘（阶段3，原样摘要）

- 题1：判定"部分正确"——baseline 没按预测漏解，而是端点值计算错误
- 题2：判定"完全正确"——但原文又说"baseline 实际没有翻车"（自相矛盾）
- 题3：判定"部分正确"——baseline 得到 m>1/2，判定为"漏掉 m<1"，最终答案判错
- 题4：判定"完全正确"——同样自相矛盾："baseline 实际没有翻车"
- 题5：判定"部分正确"——baseline 第三类处理错误；系统"最终答案正确"

## 五、⚠️ 审计更正（人类 + SymPy 裁判，关键发现）

**LLM 生成的 5 个"标准答案"里，有 3 个是错的。** 复盘 LLM 全程没发现。

| 题 | 预测表的标准答案 | SymPy 审计后的真答案 | 审计证据 |
|---|---|---|---|
| 1 | a=-1 或 a=3 ❌ | **a=0 或 a=2** | max(a²,(a-2)²)=4 → a∈{0,2}；a=-1,3 时 max=9≠4 |
| 2 | x=√5±√3 ✅ | √5±√3 | 一致 |
| 3 | m<1 或 m>2 ❌ | **m>1/2** | Δ=8m-4>0 → m>1/2；m=0 时 Δ=-4 无交点，与"m<1"矛盾 |
| 4 | (3±√5)/2 ✅ | (3±√5)/2 | 一致 |
| 5 | a=0 或 a=2 ❌ | **0≤a≤2** | 顶点 (a,-1) 在区间内即满足，故整个 [0,2] 都行 |

**修正后的逐题判定：**

| 题 | 真答案 | baseline 判定 | 系统判定 | 预测是否应验 |
|---|---|---|---|---|
| 1 | a∈{0,2} | 推理正确（终局未知） | **漏解 a=0**（只得出 a=2）❌ | 预测方向部分对（漏解确实发生，但在系统身上） |
| 2 | √5±√3 | ✅ | ✅ | 未应验（baseline 没翻车） |
| 3 | m>1/2 | ✅ **做对了** | ✅ **做对了** | 未应验；且 LLM 复盘把它误判为"错" |
| 4 | (3±√5)/2 | ✅ | ✅ | 未应验 |
| 5 | 0≤a≤2 | 推理正确（终局未知） | 推理对但**最终答案写错**（0或2）❌ | 预测方向部分对；且 LLM 复盘把错答案判为"对" |

## 六、元教训：这个实验证明了什么？

### 1. 没有裁判，每一层都会"自信地错"
- **出题层**：LLM 编造标准答案，3/5 是错的（题1、3、5），它自己毫无察觉；
- **求解层**：baseline 和系统对题3 都做对了（m>1/2），却因为参考了错误标准答案而被判"错"；
- **复盘层**：复盘 LLM 拿着错误标准答案，**把对的判成错的（题3）、把错的判成对的（题5）**。

> 这正是核心论点的实证：*在数学这类封闭系统里，任何一层失去确定性裁判，
> 都会产出看似自信、实则错误的结论。裁判的裁判也需要裁判。*

### 2. 系统的两个真实缺陷（审计后暴露）
- **题1 漏解 a=0**：分类讨论覆盖了三种情况，但"0≤a≤2 时令 f(0)=3 得 a=2"漏掉了对称情况（f(2)=3 得 a=0）。子任务拆分不够对称；
- **题5 组合阶段自相矛盾**：推理过程正确（"所有 0≤a≤2 都满足"），但组合输出的 boxed 答案写成"0 或 2"——**这正是对话里预判的"组合阶段篡改逻辑"问题**，且因验证器对区间答案 UNSURE，没被兜住。

### 3. 预测本身的价值
- 5 个预测里，3 个未应验（baseline 没翻车）——说明这些题对 LLM 还不够难，**对抗性出题难度需要再提高**；
- 2 个"部分应验"——漏解类风险真实存在，但发生在系统自己身上，说明**系统在分类讨论完备性上需要更强的验证**（例如：每种情况解出的候选值，必须代回原条件复核）。

### 4. 实验方法缺陷（记录在案）
- 我把实际输出截断到 800 字符才喂给复盘 LLM，导致它把"截断"误读成"答案没解完"；
- 复盘 prompt 没有要求 LLM 独立验证标准答案——复盘层没有裁判。
- 下次改进：不截断（或明确告知截断仅为显示）、复盘前先用 SymPy 审计标准答案。

## 七、修复后复测（2026-08-18，补充）

针对题3（判别式不等式）暴露的裁判盲区，做了三处升级并复测：

**升级**：
1. 新增 `inequality` 验证类型：SymPy `solveset`（实数域）解不等式，与声称的解集比对；
2. `satisfies` 支持链式不等式（`1<=x<=4`）；
3. `equality` 支持 `表达式 = 0` 形式的答案（此前因解析不了 `=` 导致 UNSURE 放行错误前提）。

**复测题3（m 的取值范围）结果**：

```
子任务1：标准形式（c=m²+2）        → UNSURE（多值答案，弃权）
子任务2：判别式化简                → FAIL（LLM 声称 16m+12，真值 8m-4）
   → 反馈纠错第 1 次 → PASS ✅
子任务3：解不等式 Δ>0              → PASS（m > 1/2 与真解集 Interval.open(1/2, oo) 一致）✅
最终答案：m > 1/2 ✅（正确）
```

**这次复测的意义**：纠错回路（FAIL → 反馈 → 修正 → PASS）**第一次实战成功**——
裁判当场抓住 LLM 的判别式展开错误，一次反馈就修正，然后不等式解集验证放行。
这是投名状演示视频的核心镜头：错误被确定性裁判发现，而不是靠 LLM 自查。

**仍存在的边界（诚实记录）**：
- 子任务 1 的"多值答案"（`a=1, b=-2m-2, c=m²+2`）仍会 UNSURE——下一步支持列表答案；
- 上一轮复测中出现的"常数项 m²-4 错误穿透"场景（拆解错→后续自洽地错）已通过
  `equality` 支持等式形式部分缓解，但拆解完备性验证仍需强化（对话中预判的深层问题）。

## 九、外部审计补记（2026-08-18，第三方 AI 交叉审计 + 补跑数据）

第三方 AI 对本实验做了逐字段交叉审计，发现的问题经核实如下。

### 9.1 baseline 截断掩盖了真相（实锤，已补跑）

原实验把 baseline 输出截断到 800 字符存档，复盘无法判断终局。
**已补跑全量**（`data/prediction_baseline_full.json`，未截断），结果：

| 题 | 真答案（SymPy 审计） | baseline 终局 | 判定 |
|---|---|---|---|
| 1 | a∈{0,2} | boxed {0, 2} | ✅ **对** |
| 2 | √5±√3 | √5±√3 | ✅ 对 |
| 3 | m>1/2 | m>1/2 | ✅ 对 |
| 4 | (3±√5)/2 | (3±√5)/2 | ✅ 对 |
| 5 | 0≤a≤2 | boxed [0,2] | ✅ 对 |

**结论：baseline 5/5 全对，预测的失败模式 0/5 应验。**
这组"对抗题"对 baseline 根本不够难；而系统反而 P1 漏解 a=0、P5 终局答案错误。
**本轮 baseline 表现优于系统**——此事实必须如实记录，不得包装。

### 9.2 system_ok 与答案正确性零相关（实锤）

| 题 | system_ok | 最终答案 | 子任务验证 |
|---|---|---|---|
| 1 | true | 漏解（只答 a=2）❌ | 2 PASS / 3 UNSURE |
| 5 | true | 终局自相矛盾（0或2）❌ | 1 PASS / 3 UNSURE |
| 4 | true | 正确 ✅ | **0 PASS / 3 UNSURE**（全程未验证） |

- `system_ok` 的语义只是"流程中没有 FAIL"，**不是"答案已验证/正确"**；
- 组合文本"经验证"是 LLM 写的（语言空间声称），与真实状态可矛盾（P4 全 UNSURE 却写"经验证"）。
- **修复**：① combiner 逐条标注验证状态，禁止把 UNSURE 说成已验证；② main.py 返回 `all_subtasks_verified` + 三态计数，`ok` 不再被误读为"正确"。

### 9.3 架构承诺 vs 实现痕迹（部分实锤，已修复）

| 承诺 | 审计发现 | 修复 |
|---|---|---|
| weight（权重） | 只被要求输出，main.py 从未读取 | 已用于同层子任务执行排序 |
| constraints（约束传播） | 只出现在分类提示词，无验证作用 | 已注入求解提示词并落盘记录 |
| 重试日志 | log_case 只存最终状态，重试过程零痕迹 | 新增 trace：拆解+每次求解/验证/重试全记录 |
| 拆解 JSON | 不落盘 | 随 trace 落盘 |

### 9.4 架构级发现：代入式验证对"完备性错误"失明（本审计最有价值的结论）

- P1：系统找到 a=2，代回 → 最大值=3 ✓ PASS。**它永远不知道 a=0 被漏了**；
- P5：即使对"0或2"做终局代回验证，两个候选都成立——**漏掉整个区间对代入验证是隐形的**。

> "每个候选都成立"（易）与"没有遗漏候选"（难）是两件事。
> 对"求所有可能值"类题目，需要**参数空间的覆盖性证明**（分类讨论必须证明无缝覆盖全空间、
> 每类的候选枚举对称），而不是代回验证。这解释了 system_ok 为什么 5/5 全 true 而 2 题答案错。

### 9.5 报告自美化倾向（接受批评）

此前把"预测未应验"包装为"失败得很有价值"，稀释了更硬的事实：
**system_ok 不可靠 + baseline 本轮反超系统**。本补记已按原始数据修正叙事。

## 八、对投名状的意义

这次实验"失败"得非常有价值：**预测没怎么应验，但实验本身炸出了三层"缺裁判"的连锁错误**。
把它写进投名状，不是讲"我的系统多能打"，而是讲：

> "我设计了一个对抗性实验想证明系统比 baseline 强，结果发现：**生成预测的 LLM、
> 求解的 LLM、复盘的 LLM，全都因为缺少确定性裁判而自信地错**——连'标准答案'都错了 3/5。
> 这恰好实证了我系统的核心主张：推理链上的每一层都必须挂接可验证的裁判。"
